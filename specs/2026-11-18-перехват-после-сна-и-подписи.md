# Пропажа неона и возврат системного OSD (перехват медиа-клавиш)

Дата: 2026-11-18
Статус: принято 2026-11-18, все критерии проверены

## Симптом

После некоторого времени работы NotchDeck перестаёт перехватывать клавиши яркости и громкости:
неоновая плашка не появляется, вместо неё показывается системный индикатор. Лечится только
перезапуском приложения. После обновления версии симптом возвращается сразу.

## Причины (найдены в коде и системном логе)

### 1. Подпись ad-hoc: TCC не узнаёт приложение после пересборки

`build.sh` подписывает `codesign --sign -` (ad-hoc). При ad-hoc подписи designated
requirement привязан к cdhash — он меняется при каждой сборке. Системная запись о
разрешении «Универсальный доступ» относится к старому cdhash, поэтому после обновления
TCC её отбрасывает:

```
Failed to match existing code requirement for subject com.notchdeck.app
  and service kTCCServiceAccessibility
```

Следствие: `AXIsProcessTrusted()` возвращает `false`, `CGEventTap` не создаётся,
системный OSD возвращается. Пользователь видит «неон пропал».

Проверка, воспроизведено: сборка из `Build/` при запуске через `open` пишет
`доступ AX=false`; установленное `/Applications/NotchDeck.app` — `доступ AX=true`.

### 2. Мёртвый tap не пересоздавался

`MediaKeyTap.start()` начинался с `if active { return true }`. macOS гасит tap после
сна, смены пользователя или таймаута обработчика; флаг `active` при этом оставался
`true`, и приложение больше никогда не пыталось поднять перехват. Обработчика
`didWakeNotification` не было вовсе.

## Требования

- **R1.** `MediaKeyTap.start()` не считает tap живым по одному флагу: если порт существует,
  но `CGEvent.tapIsEnabled(tap:)` ложно, мёртвый порт снимается и tap создаётся заново.
- **R2.** Приложение следит за живостью tap периодически (watchdog, интервал 3 с) и
  восстанавливает его без участия пользователя.
- **R3.** После пробуждения из сна tap пересоздаётся автоматически (наблюдатель
  `NSWorkspace.didWakeNotification`, задержка 1 с).
- **R4.** Сборка подписывается стабильным самоподписанным сертификатом, а не ad-hoc:
  designated requirement перестаёт зависеть от cdhash, и разрешение «Универсальный
  доступ» переживает обновления версии.
- **R5.** Версия приложения поднимается (2.1.0 (220) → 2.1.1 (221)), обновление
  устанавливается в `/Applications` и публикуется в GitHub Releases.
- **R6.** Существующее поведение неона и маршрутизация клавиш не меняются.

## Критерии приёмки

- **A1.** `--test-tap-watchdog` печатает `WATCHDOG PASS` и код возврата 0: погашенный
  через `CGEvent.tapEnable(false)` tap заменяется новым портом.
- **A2.** В логе запущенного приложения есть строка `keys: watchdog tap запущен`.
- **A3.** `--test-key-routing` — `KEY ROUTING PASS` (маршрутизация, повтор, mute, точный шаг,
  откат при неудачной записи, скрытый HUD).
- **A4.** `--test-keyboard-mode` — `KEYBOARD PASS: 25 checks`.
- **A5.** `codesign -d -r-` у установленного приложения показывает требование на основе
  сертификата (`certificate root`), а не `cdhash`. Первая установка после смены типа подписи
  требует одной перевыдачи разрешения (старая запись TCC привязана к прежнему cdhash);
  последующие обновления версии разрешение сохраняют.
- **A6.** Установленное приложение пишет `level: наблюдение включено (перехват=да, доступ AX=true)`.
- **A7.** `gh release view 2.1.1` подтверждает опубликованный релиз.

## Вне области

- Перехват системных баннеров уведомлений (NotchDeck их не зеркалирует — это отдельная
  нереализованная функция, симптом «системные уведомления» здесь означает индикатор OSD).
- Запись экрана и микрофона: у них свои TCC-разрешения, отдельная задача.
- Нотаризация у Apple Developer Program.
